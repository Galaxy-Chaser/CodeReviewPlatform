# 摘要与聚焦审查 · v1.25

扫描详情、修复任务清单和固定提交 PR 报告显示原报告全部发现的风险与审查状态计数。摘要始终对应保存的报告；筛选不会将计数缩小为当前页。文件数是发现中不同已记录文件名的数量，不是当前项目的文件数量，也没有重新检查源码。

## 使用

1. 在扫描详情打开“修复任务清单”，或打开 PR 报告。
2. 选择“风险范围”和“审查状态筛选”。例如高风险 + 未排除，可先处理仍需关注的高风险发现。
3. 每页最多 25 条。编号来自完整清单，筛选后出现跳号属于正常情况，便于对应完整导出。
   新筛选加载期间，旧页的翻页和问题操作暂时停用，避免将选择退回旧条件；筛选控件仍可更改。读取失败则保留原页并恢复原选择与可用操作。
4. 打开“审查问题”，填写依据并保存；也可点击“返回修复清单”取消。两种操作都保留原筛选与页位置。若决定使末页减少，返回最后仍有匹配的页；没有匹配时回到零匹配视图。
5. 导出仍为完整报告。修复清单的 Markdown、扫描 JSON、扫描或 PR 的 SARIF 包含其他页和已排除的发现。

风险组沿用原严重性：高风险为 BLOCKER、CRITICAL、HIGH；中风险为 MAJOR、MEDIUM；低风险与提示为 MINOR、LOW、INFO。未知旧风险单独计数，在“全部风险”中保留。缺少审查状态表示待审查；无法识别的旧状态显示为未知，在“全部状态”和“未排除”中保留。

“没有匹配”只描述所选条件。原报告总数和原门禁仍可见；人工排除、确认或修复中都不会消除原风险或解除验收阻断。运行中、失败或缺少完整问题列表的报告分别标明未完成或未知，不能用部分计数证明检查通过。PR 结果仍对应固定的 HEAD/BASE，不代表远程当前代码。

## 接口与资源边界

人类本机接口 `GET /api/tasks/page?id=报告编号&offset=0&risk=high&review=active` 返回当前匹配页、规范化筛选、原报告摘要和原门禁。省略筛选等同全部。允许字段仅为 `id`、`offset`、`risk`、`review`，拒绝重复字段、空筛选、未知值和其他字段。offset 为 0–10,000,000 的整数；超出当前匹配结果时返回最后可用页，而非隐藏尚有的发现。

| 字段 | 允许值 |
| --- | --- |
| risk | all、high、medium、low |
| review | all、active、open、confirmed、fixing、dismissed |

只读取已有完成报告，不执行源码、不调用模型、不新增运行依赖或常驻正文缓存。摘要只传固定大小的计数，不传路径列表、规则列表、证据、审查理由或历史。服务仍按需读取完整报告并排序；这次改进减少页面显示和传输的正文，不声明整个进程内存或报告读取成本恒定。

直接扫描与问题审查仍是人类本机操作；本地 agent 的任务协作权限没有扩大。已有任务授权、领取、证据与人工审核流程继续适用。

## 验证条件

- 所有已知风险、审查状态、旧未知值、重复发现、空结果和部分记录；大报告摘要只有固定计数。
- 组合筛选、稳定完整编号、超过两页、末页减少、全部排除、非法参数；报告内容与门禁保持原样。
- 真实 HTTP 返回匹配行，筛选前后磁盘报告字节相同，JSON 与 SARIF 仍完整。
- 可控延迟读取验证最新筛选优先，关闭或编辑后旧响应失效；失败保留原列表并恢复原选择，过期错误不覆盖新选择。
- 真实浏览器完成 62 条发现的分页与审查，组合筛选保存/取消，零匹配保留完整数和失败门禁，恢复全部，390px 布局，完整 Markdown/SARIF 下载。
