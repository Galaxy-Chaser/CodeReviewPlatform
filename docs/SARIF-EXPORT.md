# 分享标准检查报告（v1.23）

SARIF 2.1.0 是代码检查结果交换格式。v1.23 可以将一份已完成的扫描或固定提交 PR 报告导出，让支持这一格式的工具读取发现。运行依赖没有增加。

## 页面中下载

1. 打开“扫描历史 → 查看详情”或“代码审查与证据”中的 PR 检查报告。
2. 点击“导出 SARIF”，再点击“下载副本”。也会显示本机保存位置。
3. 在对应项目或仓库中使用下载的 `.sarif` 文件。文件路径以扫描项目根目录或 PR 仓库根目录为起点；如果项目登记的是仓库子目录，需要先正确映射根目录，不能直接当作仓库根目录位置。

导出完整报告的全部发现，包括其他页和“已排除”的问题。人工判断保留为状态，不隐藏问题或降低原风险。原 JSON 报告与 Markdown 修复/验收清单继续保留；SARIF 主要用于分享发现，完整交付证据仍看原报告。

未完成或失败的检查不能导出 SARIF。一份已经完成但质量门禁失败或未知的报告可以导出，保留原门禁状态。没有发现的已完成报告也能导出；零发现仍不代表构建、测试、当前源码或所有业务要求已经通过。历史报告按原记录导出，不重新扫描，也不改写原验收结论。

## 保存了什么

| 内容 | 导出规则 |
| --- | --- |
| 检查来源 | 本地规则为 `CodeHealth local rules`；导入的 SonarQube 问题在独立 `SonarQube` run 中，转换工具另行标识 |
| 规则与风险 | 保留原规则编号和原风险；高/严重风险映射 `error`，中风险 `warning`，低风险/提示 `note`；不制造安全评分或精度保证 |
| 文件与行号 | 保留项目相对路径，正确编码空格、中文、`#`、`?`、`%`；新的 Sonar 导入保留未知行号，页面与 Markdown 显示“行号未提供”，SARIF 不填虚假第 1 行 |
| 问题说明 | 保留原说明，包括正常换行；不包含源码片段或自动修复代码 |
| 审查 | 保留 `open/confirmed/fixing/dismissed` 状态；不导出审查正文，不设置 SARIF suppression |
| 范围与版本 | 保留原 `project/changed/github` 范围、平台门禁和报告编号；存在时保留 SonarQube 自身门禁与记录的源码指纹；PR 保留原仓库、HEAD 与 BASE |
| 不包含的字段 | 日志、配置、凭据字段、源码片段、人工证据正文和本机源码根目录；问题说明与相对文件名仍是原记录 |

本地规则版本只在原报告已记录时输出；SonarQube 版本未记录则省略。没有可靠的源码行哈希时不生成 SARIF `partialFingerprints`。工具可能自行根据对应版本的源码生成自己的定位信息。

旧报告如果已经由旧版保存为第 1 行，无法可靠判断它原本是否缺少行号，因此保留旧记录。要获得真实的未知位置语义，需重新进行检查；不猜测并改写历史。

`%SRCROOT%` 表示需要映射的源码根目录，绝对本机路径被省略。这采用 [OASIS 规范 §3.14.14](https://docs.oasis-open.org/sarif/sarif/v2.1.0/os/sarif-v2.1.0-os.html) 允许的省略方式，避免导出机器用户名或构造虚假的根目录。

## 接口与边界

本机人工接口 `POST /api/export` 接收 `{ "scanId": "已保存报告 UUID", "kind": "sarif" }`，返回 `file/url/path`。读取返回的本机 `url` 可下载文件，响应类型为 `application/sarif+json`。不是 agent 授权接口；现有授权与本机访问边界不变。

每份最多 20,000 条发现，输出最多 16 MiB UTF-8。超限拒绝整份导出，不默默截断。规则编号最多 500 字，问题说明最多 10,000 字，相对路径最多 1,000 字。拒绝绝对路径、上跳路径、空路径段、非法行号、未知分析来源/风险、无效字符或不完整报告。新文件先写临时文件，成功后发布；失败不会留下可下载的半份结果。已导出的 `.sarif` 文件包含在数据备份与恢复中。

平台不导入外部 SARIF、不执行其中的内容，也不自动上传 GitHub、发表评论或启动其他分析器。

## 与已有工具结合

[reviewdog](https://github.com/reviewdog/reviewdog#sarif-format) 支持以 `-f=sarif` 读取 SARIF。它可以结合自己的差异筛选处理发现；平台导出的发现保持原样，后续筛选结果不作为平台门禁证据。

[GitHub code scanning](https://docs.github.com/en/code-security/reference/code-scanning/sarif-files/sarif-support) 支持 SARIF 2.1.0。若自行上传，需要正确的仓库、提交、根目录映射与 GitHub 配置，并遵守当前上传和显示上限。平台没有代为上传，也没有验证远程接收结果。GitHub 展示可能少于导出总数，完整发现仍保留在下载文件中。

另外使用隔离的开发校验工具，将八份代表性结果对照 [OASIS 官方 schema](https://docs.oasis-open.org/sarif/sarif/v2.1.0/os/schemas/sarif-schema-2.1.0.json) 完整校验，包括 20,000 条发现。校验记录保存在 `outputs/sarif-validation/validation-report.json`，开发工具不进入源码包或运行依赖。这些验证不代表实际 GitHub 上传、外部工具处理或真实 Sonar 服务已经验证。
