# 自动验收使用说明 · v1.23

平台现在分别提供自身自动测试、真实页面回归和项目业务场景绑定。三个入口有不同的验证范围，应结合使用。

## 安装与准备

需要 Node.js 20 或更新版本。在项目目录执行 `pnpm install --frozen-lockfile`，使用随项目提供的锁文件安装依赖。也可以执行 `npm install`；此方式不使用 pnpm 锁文件。便携源码包包含锁文件，不包含已安装依赖。

依赖为 Playwright 1.63.0（页面回归）和 fast-xml-parser 5.11.2（具体测试结果解析）。安装时应包含开发依赖。未安装 XML 依赖时，原有本地检查仍可使用，但绑定测试不能获得可核实结果。

Windows 页面回归默认使用已经安装的 Microsoft Edge，无需下载独立浏览器。其他系统默认使用 Chromium，需要执行 `npx playwright install chromium`。缺少浏览器、启动失败或超时会记录失败，不会跳过后宣布通过。固定运行时限为 150 秒。

浏览器支持说明见 [Playwright 官方文档](https://playwright.dev/docs/browsers)，解析器说明见 [Fast XML Parser 官方仓库](https://github.com/NaturalIntelligence/fast-xml-parser)。

## 平台自身迭代

1. 在“验收流水线”点击“查看本轮验收”→“开始本轮验收”。平台先自检，通过后继续十三项页面回归。
2. 查看本轮汇总、分项报告和截图。只有两类完整证据对应执行开始时的同一版代码，才能通过。也可分别使用原有两个检查入口定位问题。
3. 核对业务需求及页面效果。自动回归覆盖固定流程，新增功能仍需要新增对应验证。
4. 代码变化后重新执行两个检查。旧成功结果保留，但不能证明新代码通过。

页面回归执行以下固定流程：

| 流程 | 实际核对内容 |
| --- | --- |
| 项目登记 | 页面注册本地示例项目并显示结果 |
| 重复登记 | 重复项目被拒绝，已有项目仍保留 |
| 本地扫描 | 从页面发起真实扫描，等待完成并打开详情 |
| 交付证据 | 填写五类证据并保存，确认验收状态更新 |
| 报告导出 | 实际下载 JSON 与空报告 SARIF，核对内容对应本次报告 |
| 场景复验 | 保存方案、扫描、记录失败受阻、修改为通过并保留失败历史 |
| 代码变化 | 修改隔离示例源码，确认旧验收显示失效并阻断 |
| 大量问题 | 62 个真实发现按 25/25/12 翻页，第二页连续保存两项审查并返回原页，取消第三项编辑；完整下载 62 条 Markdown 与 SARIF，保留审查状态和失败门禁 |
| 按需配置 | 默认收起可选设置，拒绝非法地址并保留旧设置，保存有效本机配置 |
| 多 agent 协作 | 通过页面创建需求和任务，两个真实授权参与者领取/提交，拒绝重复领取；定时同步自动更新，搜索和编辑草稿保留；人工审核和知识发布显示正确 |
| 任务交接 | 第二个真实页面在 agent 领取期间修改需求，原页面自动提醒；显示新范围与验收条件，拒绝旧需求续期；释放、按新条件更新再重新领取；延迟编辑读取不能覆盖新草稿，任务再次更新后仍标明旧证据，检查窄屏详情 |
| 页面释放 | 关闭详情清除隐藏正文，离开列表释放缓存并中止读取 |
| 窄屏操作 | 在 390 × 844 视窗打开导航和报告，检查无横向溢出 |

回归使用临时数据目录、临时源码和独立浏览器配置；仅访问自己的本地服务。结束后清理临时环境。每项保存真实页面截图，失败后其余流程记为未执行。十三项全部完成且平台源码核对一致，才显示通过；缺少步骤、重复步骤或执行中代码变化均不能通过。

平台入口保存报告、截图及最新一次检查引用到当前数据目录。备份保留这些文件；缺少被引用的截图会拒绝创建不完整备份。执行中不能重复启动，也不能同时运行平台自身检查或备份。

终端可运行 `npm run check:iteration` 连续执行本轮验收，报告与截图保存在 `outputs/iteration-check`。它向终端返回失败状态，便于自动流水线阻断。独立运行不会自动替换页面的最新检查。

原有 `npm run check:platform` 和 `npm run check:browser` 保留，独立结果分别放在 `outputs/platform-check`、`outputs/browser-check`。单独页面回归不自动执行整套 Node 测试。

## 中断、失败与备份

本轮验收先写入未完成的失败报告，再登记最新引用。运行中可以刷新查看当前阶段；启动按钮暂不可用。自检失败立即停止，不拿旧页面报告补齐；服务中断后重新打开也不会显示旧成功。本轮检查和独立检查互斥，运行时不能创建备份。

完成后可以下载组合报告、平台自检原始报告和页面截图。数据备份包含组合报告、引用的分项报告和截图；引用内容缺失时不能创建不完整备份。恢复还会核对分项内容与组合证据一致。

## GitHub 自动验收

`.github/workflows/acceptance.yml` 在 main 分支提交、拉取请求及手动触发时运行。采用 Windows 与 Node 24，确保 Windows 环境测试实际执行而不跳过；按锁文件安装依赖，使用独立 Chromium 浏览器，运行同一套 `check:iteration`。

失败会使任务失败；成功或失败都尝试上传本轮报告与截图，保存 14 天。任务只授予仓库读取权限，不使用平台生产数据、项目 Token 或 Sonar 配置。它提供自动检查结果，尚未设置 GitHub 分支保护；是否允许合并仍由仓库规则决定。

## 项目业务场景自动绑定

在“编辑验收方案”中，为需要自动核实的场景填写“绑定自动测试”，格式为 `测试类#测试名称`，例如 `demo.FlowTest#normal`。名称以实际 Surefire/Failsafe 报告的 classname、name 为准，不是任意命令。参数化测试应填写具体报告名称。

绑定要求完整体检；保存方案后重新执行完整检查。平台从本次 Maven 构建产生的新报告中精确匹配结果，冻结在本次验收记录中：

| 实际证据 | 场景结果 |
| --- | --- |
| 全部匹配测试通过且构建完成 | 自动通过 |
| 任意匹配测试失败或错误 | 自动失败，验收受阻 |
| 未匹配、跳过、旧报告、报告不一致或无法读取 | 待验证，不能通过 |
| 未执行完整项目构建 | 待验证，不能通过 |

自动结果不能人工改成通过或不适用。修复代码或绑定名称后保存方案并重跑；未绑定场景继续真实执行并登记人工证据。报告不保存测试日志或失败堆栈，仅保留匹配名称、状态和来源路径。

自动绑定证明指定测试确实执行并产生结果，不证明断言充分、覆盖率达标或所有需求满足。真实 Java/Maven/Sonar 完整流程仍需要项目环境就绪；本轮仅对解析与验收逻辑使用代表性报告验证，没有执行真实 Java 构建。
