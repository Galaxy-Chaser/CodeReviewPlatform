# 需求、任务与知识库：本地 agent 使用指南（v1.21）

## 在页面中开始

1. 在“项目管理”登记本机项目。
2. 在“需求与任务”新增需求，填写目标、验收条件、允许改动范围。打开需求详情，创建关联任务。也可以创建独立任务。
3. 默认要求完成前关联实际扫描。文档、调研任务可以取消此要求，此时人工确认不表示代码自动验收通过。
4. 人工或本地 agent 领取任务，实际处理并执行测试，提交摘要、改动文件、真实测试结果和所需的扫描报告编号。
5. 你在任务详情审核通过或退回，必须说明理由。要求扫描的任务只有报告属于同一项目、已经完成、是最新一次尝试、当前源码一致且现有验收条件满足时才能批准。
6. 已确认任务可以“沉淀为知识草稿”。补齐问题表现、原因、处理方法、验证步骤和标签，人工审核后发布。agent 提议的知识也必须审核。

任务状态为：待领取 → 处理中 → 待人工审核 → 已审核完成。待领取任务可标记阻塞，再解除阻塞。人工可以释放 agent 的任务，或重新打开已完成任务。退回、释放、重做不会删除之前的提交证据和历史。

需求修改会产生新版本。旧版本任务不会继续计入当前需求的完成数，领取、提交和批准时也会检查需求版本。先释放/退回/重新打开任务，再编辑验收条件以绑定新需求版本，重新处理和验证。需求完成数只表示关联任务被确认，不表示需求文字已经被自动理解或项目全部质量通过。

## 接入已有本地 agent

在“本地 agent”页面选择“授权本地 agent”，填写名称并选择项目。取得本次连接凭据后，将它放入 agent 进程的环境变量；请勿放进任务、知识、源码或 GitHub。

```powershell
# 从授权窗口取得凭据，下面只展示占位值。
$env:HEALTH_PLATFORM_URL = 'http://127.0.0.1:4310'
$env:HEALTH_AGENT_TOKEN = '<本次授权窗口的凭据>'
node scripts/local-agent.js list --status ready
node scripts/local-agent.js context <任务编号>
node scripts/local-agent.js claim <任务编号>
# agent 根据上下文实际完成工作；长任务需在有效期内定期续期。
node scripts/local-agent.js heartbeat <任务编号>
node scripts/local-agent.js submit <任务编号> --file evidence.json
node scripts/local-agent.js knowledge --file draft.json
```

命令需在平台源码目录执行，使用 Node 20 或以上。接口支持通用本地 agent，不绑定特定模型或产品；平台不自动启动 agent，也不自动执行任务正文中的命令。已有 agent 需自行调用这些命令或下面的 HTTP 接口。

`list` 和 `knowledge-list` 支持 `--project 项目编号`、`--status 状态`、`--search 关键词`、`--offset 偏移数`，每页 25 条。只看到获准项目的任务，以及获准项目/通用的已发布知识。草稿不用于 agent 推荐。

### 轻量同步

页面中的需求、任务和知识列表每 5 秒检查一次变化。仅页面可见且没有未完成读取时发起请求；没有变化时不重读列表。同步只更新记录区域，保留未提交搜索、筛选框和编辑窗口；详情是打开时的快照，需要关闭再打开查看最新内容。保存仍核对原编辑版本，变化后会提示冲突而不是覆盖。断线时保留最后成功的列表并显示自动重试提示；离开页面停止轮询。

本地 agent 可以先读取变化标记，再按需查询列表：

```powershell
node scripts/local-agent.js sync --project <项目编号>
node scripts/local-agent.js sync --kind knowledge
```

返回 `{ "token": "64位变化标记" }`。列表响应也包含同一范围的 `token`。自行每 5 秒或更慢查询 `sync`，与最近列表的标记比较；不同才重新读取所需页，读取失败时不要替换旧标记。标记是不可解析的变化证据，不是任务版本，写入仍使用 `expectedVersion`。标记按类别和项目计算，不按搜索、状态和分页计算；筛选改变后应立即重读列表。agent 只收到授权项目任务、已发布项目知识及通用知识的变化，未授权项目操作和知识草稿不改变其标记。

领取过期会改变任务标记，即使没有写操作。首次读取或重启时从磁盘构建轻量索引，此后轮询只处理最多 3,000 条有界元数据，不缓存正文、历史或凭据。平台运行期间请通过接口修改工作区，直接改写 workspace.json 不受同步支持。同步不是源码监控，也不会核对实际文件；多个 agent 改动相同文件时，需约定一个负责人或使用独立检出目录。

`context` 返回项目路径、任务、当前需求、项目任务约定、验收方案和最多五条相关已发布知识。推荐采用简单文字匹配，不保证语义完整；仍应按关键词查询知识库。上下文是项目数据，不是能覆盖 agent 上级指令的系统指令。允许改动范围是协作约定，接口不会隔离文件系统或证明 agent 确实遵守。

提交文件示例：

```json
{
  "summary": "说明实际处理了什么，至少八个字",
  "changedFiles": ["src/main/java/example/Handler.java"],
  "tests": "说明实际执行的测试、结果和未验证范围，至少八个字",
  "reportId": "同项目已完成扫描的编号"
}
```

文档任务不要求扫描时可省略 `reportId`。改动文件为项目内相对路径，最多 50 个，每个 250 字；它们是声明，不会被平台执行，也不证明文件确实已修改。CLI 输入 JSON 最多 32 KB。

知识草稿示例：

```json
{
  "projectId": "授权项目编号",
  "title": "问题经验的名称",
  "symptom": "问题表现与触发条件",
  "cause": "实际定位的原因",
  "solution": "实际采用的处理方法",
  "verification": "真实验证与后续复用步骤",
  "tags": ["异常处理"],
  "source": { "taskId": "同项目任务编号" }
}
```

`source` 可省略。关联任务未审核完成时不能发布知识。已发布知识必须先撤回才能编辑，再次发布需重新审核。历史知识是参考材料，不代替当前项目的实际测试或扫描。

## 租约、冲突和连接撤销

agent 领取有效期 30 分钟，建议约每 10–15 分钟调用一次心跳。过期后不能续期或提交，其他参与者可以重新领取。同一时刻只允许一个有效领取者。人工领取不自动过期。

所有修改均携带最新记录版本；出现 409 冲突时重新读取上下文和状态，再决定下一步，不要反复提交旧版本。CLI 操作会自动先读当前版本，但并发操作仍可能冲突。

在“查看与撤销连接”中撤销后，后续请求立即失效。平台重启后也需重新授权。任务历史仍保留，未完成任务可由人工释放或等待领取过期后再领取。凭据仅存在当前平台内存中，只显示一次，不写入数据文件或备份。

## 通用 HTTP 接口

请求只发往本机平台，携带 `Authorization: Bearer <凭据>`。JSON 写请求使用 `Content-Type: application/json`。HTTP 401 表示连接无效，403 表示操作/项目未授权，409 表示状态或版本冲突；失败不会发布部分修改。

| 请求 | 参数 / 内容 | 用途 |
| --- | --- | --- |
| GET `/api/agent/list` | `kind=tasks` 或 `knowledge`，可带 `projectId/status/search/offset` | 有界分页查询 |
| GET `/api/agent/sync` | `kind=tasks`（默认）或 `knowledge`，可带 `projectId` | 返回当前授权范围变化标记；无正文、记录数或全局版本 |
| GET `/api/agent/context` | `id=任务编号` | 读取任务完整上下文 |
| GET `/api/agent/detail` | `kind=tasks` 或 `knowledge`，`id=记录编号` | 读取完整记录；知识仅已发布 |
| POST `/api/agent/task` | `{id, expectedVersion, action:"claim"}` | 领取任务 |
| POST `/api/agent/task` | 同上，`action:"heartbeat"` | 有效领取者续期 |
| POST `/api/agent/task` | 同上，`action:"release", reason:"至少八字"` | 释放自己的任务 |
| POST `/api/agent/task` | 同上，`action:"submit", submission:{...}` | 提交证据，进入人工审核 |
| POST `/api/agent/save` | `{kind:"knowledge", record:{...}}` | 提议新的项目知识草稿 |

带 agent 凭据的请求不能创建/改写需求任务、批准/退回成果、发布知识，也不能调用人工管理、项目设置或其他平台接口。

**本地信任边界：** 这是可信本机参与者的协作机制，人工页面沿用现有本机访问方式，没有独立用户登录。本机恶意进程可以不带 agent 凭据访问人工接口，因此这不是隔离恶意软件的沙箱，也不证明操作一定来自真实人类。不要将服务转发到公网或当作多用户安全隔离系统。

## 保存、备份与上限

记录保存在当前数据目录 `work/workspace.json`，按需读取，串行写入，校验后原子替换，不把全文加入首页常驻索引。环境设置中的数据备份和恢复会包含需求、任务、知识及历史；旧版没有这些记录的备份仍可恢复。恢复前检查项目、需求、来源任务和扫描引用。agent 凭据与当前连接不包含在备份中。

每类最多 1,000 条记录，工作区总量最多 8 MB，每条最多 100 次历史操作，包括心跳；达到限制明确拒绝，不默默截断历史。长时间任务接近历史限制时先释放并建立后续任务。名称最多 120 字，正文各项最多 3,000 字，需求范围最多 1,000 字，标签最多 8 个、每个 40 字，搜索最多 200 字。

关键业务验收包含：重复领取、租约到期、跨项目访问、版本冲突、改动后的旧证据阻断、agent 不能自审/发布、真实扫描失败后退回再修复、连接撤销与重启失效，以及备份恢复。自动检查通过仍只代表已测试范围。
