# 简洁使用与轻量运行（v1.21）

## 先选要做的事

| 目的 | 页面 | 结果边界 |
| --- | --- | --- |
| 检查本机代码 | 项目管理 → 开始检查 | 本地 Java / SQL 规则或本次 Git 改动；不编译、不运行测试 |
| 确认交付能否验收 | 验收流水线 | 实际门禁、代码版本、场景和交付证据；未验证不会当作通过 |
| 审查 PR、记录证据 | 代码审查与证据 | 读取固定 PR 提交检查并在本机保留报告；不执行 PR 代码 |
| 管理需求和处理过程 | 需求与任务 | 明确目标、允许范围、提交证据与人工审核 |
| 复用问题经验 | 问题知识库 | 经审核发布的原因、处理与验证步骤，仍需验证当前场景 |
| 让本地 agent 参与 | 本地 agent | 指定项目的任务领取、续期、提交与知识草稿；直接扫描和问题审查接口暂未开放 |

侧栏按“检查与验收”“任务与知识”“设置与整理”分组。窄屏点击“展开功能导航”显示完整名称；点击入口或按 Escape 收起。窗口较矮时导航可独立滚动，配置入口不会被底部装饰遮挡。

## 最少配置开始使用

启动平台 → 添加项目 → 本地规则检查。无需 JDK、Maven、SonarQube、Docker 或分析 Token。任务、知识和 agent 协作也不依赖 SonarQube。

需要实际构建、测试与质量分析时，在“环境设置”点击“配置完整体检”，展开地址、JDK 8、JDK 21 和分析 Token。JDK 8 用于业务编译/测试，JDK 21 用于分析器。配置只接收本机 SonarQube 地址；无效保存会在表单内显示原因，并保留原设置。

已有本机 SonarQube 可直接使用；Docker 服务管理单独收起，平台不会安装 Docker。需要时点击“检查环境”读取真实状态；这个按钮不会启动服务或安装软件。

分析 Token、GitHub Token 与 agent 凭据只存在当前运行进程，不写入配置、备份或浏览器持久存储，重启后重新提供。GitHub 访问配置默认收起，公开仓库读取无需 Token。启动环境变量继续支持 `JAVA8_HOME`、`JAVA21_HOME`、`SONAR_TOKEN`、`GITHUB_TOKEN`，见 README 和 [agent 使用指南](LOCAL-AGENTS.md)。

## 连续审查

打开修复或 PR 清单中的问题，填写判断依据并保存后，自动回到原来的清单页。可继续审查下一条，也可在审查表单点击“返回修复清单”取消本次未保存编辑。问题中心的独立审查仍返回问题中心。审查不会删除发现或解除自动门禁。

关闭报告、改看其他详情或进入编辑窗口后，旧的扫描/流水线刷新结果不能覆盖当前内容。详情读取失败后可重试。

## 内存与读取策略

- 需求、任务和知识列表在可见页面每 5 秒检查小型变化标记，无变化时保留页面。同步保留搜索草稿和编辑窗口，隐藏页面暂停，离开页面停止，连接中断保留内容并重试。agent 可用 `sync` 命令按需同步，见 [使用指南](LOCAL-AGENTS.md)。
- 首页读取摘要；扫描详情只传显示证据，不传完整问题、文件清单和审查历史。服务仍按需读取完整报告文件。
- 历史、修复清单和 PR 问题每页最多 25 条；修复清单按完整风险顺序编号，导出仍包含全部问题。
- 离开列表中止未完成读取并清除旧列表缓存，返回时重新按页读取。
- 关闭详情清除隐藏的正文、代码、截图和编辑快照，历史记录仍保存在磁盘。
- 扫描期间避免并行叠加轮询；隐藏页面暂停页面轮询，服务端扫描仍继续。没有扫描时不启动周期轮询。
- 本地规则检查线程按需创建并退出；现有报告和协作正文不加入首页常驻数据。

“环境设置 → 运行状态”显示实测平台进程内存。它不包含浏览器、JDK、Maven 或 SonarQube。v1.18 在本机独立实例空闲时约 45–46 MB，30 次小型示例本地扫描完成后约 73 MB，主服务堆约 11 MB。样本不证明所有项目都有相同占用，也没有作为前后降幅比较。大项目、并发请求和构建会使用更多内存。

## 验证

完整自动验收保留原有八类页面流程，新增按需配置保存/拒绝、关闭详情与离开列表释放数据两类验证，并检查窄屏文字菜单；另用 62 个问题验证翻页、审查和完整导出。全部十一类当前流程和平台测试均通过，才计为本轮通过；旧版缺少新增流程的结果不能冒充完整通过。
